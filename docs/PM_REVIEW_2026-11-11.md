# XR Creations / 本轮项目经理评审

2026-11-11 · 检查范围：仓库现状、原型目录、入口与声音实现。部署和真实设备结果另行记录。

## 确认的问题

**入口尚未成为真正的网站。** 本轮开始时 `xr-works/main` 为 `82291316ca06bb8e6382a02d9a1f83dfbe4e3469`，仅含 README、四份研究文档和一份带测试的手势稳定器；没有 `index.html`、独立应用或网站部署流程。Portfolio 的 `Applications.jsx` 把 XR Works 按钮指向 GitHub `docs/TEST_TABLE.md`，而非一处可以直接体验的网站。用户感受到的“主页没做好”有明确依据。

**混乱集中在入口和重复运行时。** `xr-works` 本身只有 `main` 一个分支、零个 PR；不应把它写成“该仓库分支失控”。实际应用仍分散在 `performable-music/spatial-playground/`，多个面向相近动作的页面各自维护 UI、声部与手部响应。Portfolio 还保留大量历史发布分支；保留的分支名不等于仍在开发。

**持续轰鸣有具体实现来源。** `instrument-audio.mjs` 在本轮前以 `Math.max(gate, presence * .40)` 控制持续声，只要检测到手，即使没有明确演奏动作也打开声层；它混合了低音三角波、锯齿波与持续滤波。`gesture-score-audio.mjs` 另有固定低音 drone 与持续调度的四小节伴奏。二者不能仅靠改一个宣传标题解决，必须分别确认音门、默认音色和结束行为。

“归档”在本轮指目录地位与未来开发方向。它不等于删除远端分支、移除静态文件或破坏旧外链。本轮没有自动删除旧应用。

## 项目管理收敛规则

1. **一处功能只有一个正本。** 首页是入口，`apps/studio/` 是四项作品共同 runtime，音乐实验与 Greenhouse 各守原仓库。跨仓库引用记录具体 commit。
2. **同一时刻只收尾两条生产线。** 当前为网站／输入声音基线，以及四作品中由作者试玩选出的主项。四个原型是用来选择，不是四份并行展览制作承诺。
3. **不以数量算进度。** 新增模式前先说明它使哪个动作更清楚、哪段听感更好，或哪个完整环节得以结束。
4. **技术与艺术各自验收。** 单元测试、浏览器可用、头显可用、听感可用和完整作品是五个不同判断。
5. **每个释放都能收住。** 静音、追踪丢失、页面离开、退出 XR 与重复进入不得留下持续声或伪造交互。

## 下一次作者试玩只需做的选择

- 四个作品各玩一遍，选出一个“想重复玩”的主项；其余保持研究卡，不立即扩量。
- 在 Hand / Synth / Space 新声音里判断：什么动作感觉像演奏，什么音色仍不舒服。反馈具体到动作与时刻。
- 给 Destiny 2 切片时标注职业、技能、准备／持续／释放／命中／收束阶段。以实际切片更新职业映射。
- 头显验证记录设备型号、浏览器版本、左右手丢失、重新捏合、退出、声音解锁，以及一段不剪辑演示。
