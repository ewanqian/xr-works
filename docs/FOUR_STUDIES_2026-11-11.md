# Four Studies / 四个空间作品原型

2026-11-11 · XR Creations · Ewan Qian

## 本轮交付边界

四项使用同一个 `apps/studio/` 运行时：真正的 WebGL 三维顶点与透视、WebXR 逐眼渲染、手部捏合、控制器扳机、桌面键盘、鼠标和触屏，以及共同的声音、静音、重置、动作谱导出和单次回放。没有另起四套项目。无法创建 WebGL 的浏览器进入“兼容预览”：以 Canvas 2D 投影相同的三维点线与透视矩阵，保留交互和声音，同时禁用 XR；它不被作为 WebGL 或头显验证证据。

这四项是有完整起止的小型作品原型。它们尚未成为展览作品；真实 Quest / Apple Vision Pro 的手部舒适度、定位、听感和帧率仍需设备验收。桌面按钮使用合成输入，不能据此宣称完成了头显手势测试。

声音默认关闭，需主动点击开启。所有声音均为原创程序合成的有限事件，使用有终点的包络与节点释放；没有自动循环背景音、常开低音或空闲轰鸣。静音、页面隐藏、头显退出和跟踪丢失会停止相关声音。音质是供作者试听选择的起点，并非可演出级音乐已经验收。

## 01 / 掌中残响 — Held Resonance

**艺术问题：一个动作，给空间留下多少余音？**

打开页面时看到五根置于真实深度中的细弦。演奏者选一根，按住／捏合以积累张力，然后放开。声音只在释放时出现，按住的时间改变音尾与形态展开；不操作时回到安静。六次有意的释放组成一个短句，最后留出余音并结束。

| 层次 | 原型行为 |
| --- | --- |
| 输入 | 选弦、按住、释放；桌面方向键与空格、触屏、XR 捏合共用逻辑 |
| 声音 | 温和的正弦分音，离散调音；最长音尾约 1.6 秒 |
| 空间 | 弦张力、前后深度、释放后的局部波纹 |
| 发展 | 同一动作通过位置和持续时间形成区别 |
| 结束 | 六次释放完成；可以单次回放和导出相对时间动作谱 |
| 工作坊连接 | Minimal Input Lab 的单输入关系；Personal A/V Instrument 的 Trigger / Continuous / State |

**下一阶段：** 用真实材料的一小组自录击打／摩擦样本做 A/B 试听，比较“好听”与“可控制”是否同时改善；把释放前的张力更直接地映射到视觉，保持零输入静音。先完成一段 30–60 秒表演，再增加音色。

**验收：** 空闲 10 秒无声；追踪丢失不被当作释放；六次动作中至少三种音尾明显可辨；回放一次后自动结束；使用者能不看说明主动找到第二种演奏方式。

## 02 / 空间铸谱 — Score Foundry

**艺术问题：怎样把一次选择，排成一段可以重演的空间？**

四个节点分别是“点、线、面、息”。触发前三者产生短声音和空间形态；“息”只留下视觉事件与时间标记。八次选择构成一段动作谱，间隔也属于作品。回放保留真实相对时间，执行一遍便停。

| 层次 | 原型行为 |
| --- | --- |
| 输入 | 四选一，然后确认；1–4 选位、空格触发或 XR 指向后捏合 |
| 声音 | 三种音高与空间声像，“息”没有音频事件 |
| 空间 | 点、线与面在不同深度出现，八个时间标记显示结构 |
| 发展 | 起点、连接、展开与停顿形成顺序 |
| 结束 | 第八次选择完成；回放、停止回放、JSON 动作谱导出 |
| 工作坊连接 | One-Button Input 的状态；Scene Forge 的空间编排；Show Score 的记录与重演 |

**下一阶段：** 对接已有 Show Score schema，加入可编辑的顺序、可替换的个人素材与固定长度演出练习。当前导出的 `xr-creations-actions` 是独立动作谱格式，尚未宣称能直接导入 Ableton、Max 或已有 Show Score 播放器。

**验收：** “息”确实不产生声音；真实停顿保留；长按不产生重复触发；回放不循环；同一动作谱的桌面与 XR 表现遵守同一状态规则。

## 03 / 掌上星图 — Palm Atlas

**艺术问题：怎样先学会看见一个位置，再把它变成自己的符号？**

七个位置按“始、引、转、衡、合、映、归”的顺序被连接。光环提示下一位置，演奏者主动确认；错误选择给出明确的下一位置，不跳关。最后一次确认闭合符形，声音也完成收束。

这里的七个名称与图形是**当代创作词汇**，没有被表述为史料中的道家掌诀、法事或真实术式。既有传统文化研究仍保留其独立文献与来源。

| 层次 | 原型行为 |
| --- | --- |
| 输入 | 寻找位置、选择、确认；目标必须符合当前步骤 |
| 声音 | 每次正确确认有离散清音，错误不会连续报警 |
| 空间 | 七个有深度差的位置，逐步连线而非自动播放完成图 |
| 发展 | 从认位到构成，逐步建立动作记忆 |
| 结束 | 七次正确确认后闭合，留下可以记住的整体 |
| 工作坊连接 | Hand Seal Trainer 的认位与纠错；Phalanx 的有意确认；Gestural Atlas 的符号组合 |

**下一阶段：** 将已验证的手部标注和单手校准接入此学习过程，让提示真正依附指节；加入示范、逐步练习、撤去提示三个阶段。当前原型通过空间目标与捏合确认，尚未实现真实拇指掐指节识别。

**验收：** 选错位置不会推进；每次确认后下一步清楚；七个步骤可由屏幕按钮完成；丢手不会伪造确认；至少一位首次使用者能完成后复述规则。

## 04 / 共生之庭 — Garden of Signals

**艺术问题：当空间开始回应，你还需要一直控制它吗？**

演奏者从四个入口投入六次短脉冲。传播在三维网络中展开，声音是相互呼应的短和声。第六次后暂停输入三秒，系统进入安定状态，网络保留痕迹而声音结束。停止操作成为结构的一部分。

| 层次 | 原型行为 |
| --- | --- |
| 输入 | 从四个入口选择并触发；触发间隔有下限 |
| 声音 | 事件驱动的有限和声，每个事件有独立结尾 |
| 空间 | 67 个三维节点及邻接线，波前驱动局部亮度 |
| 发展 | 种子、传播、相互叠加、主动停手 |
| 结束 | 六次输入后静置三秒，进入平衡态 |
| 工作坊连接 | Organic Fields 的动作场；Neural Field 的传播；Quiet / Active 状态设计 |

这是一种可解释的传播视觉机制，并非神经元模型、粘菌算法或生态模拟的科学复现。

**下一阶段：** 引入一个真正可比较的传播机制，再决定它是否支撑作品叙事。比较局部扩散、阈值传播与具有记忆的连接，只保留能被观众感知到的差异。不要同时扩成三个新应用。

**验收：** 空闲不会自行完成；第六次后必须实际留白；过快输入不会叠出音量风暴；传播具有空间关系；完成之后没有残留持续声。

## 共享功能与数据边界

- `studio-core.mjs`：状态推进、目标确认、有限事件记录与导出。
- `studio.mjs`：WebGL、WebXR、声音、页面交互与一次回放。
- `index.html` 与 `studio.css`：四个 URL 参数入口的同一界面。
- 导出的动作谱仅包含选项、相对时间、有限强度和静音事件；不含手部逐关节录制，也不向服务器上传。
- WebXR 当前使用眼手方向选择空间目标与拇指／食指距离阈值。追踪丢失取消正在保持的动作；恢复后需先张开再捏合，避免把重现的旧手势误当新动作。
- 进入头显前选择作品并开启声音；空间中有本作品进度与动作提示板。退出使用头显系统菜单。头显内作品切换、独立静音按钮与左右手配置留到设备评审后收敛。

## Destiny 2 三职业扩展

保留为独立的 fan-study 路线，不混入上述四个原创作品的名称与素材。下一批输入为用户提供的音乐／动作切片，字段建议为：`class`（Titan / Hunter / Warlock）、`subclass`、`ability`、`clipIn`、`clipOut`、`phase`（prepare / hold / release / impact / recovery）、`audioRole`（cue / body / tail）。

Warlock 的现有 motion-first PR #51 仍是研究基础，不能因为代码存在就当作已验证的实时体验。三职业必须分别定义动作语法；泰坦、猎人与术士不会统一成一种剑指触发。切片到来前只保留入口与映射计划，不虚构完整音频资产。
